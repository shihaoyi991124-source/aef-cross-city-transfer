# Benchmark data prerequisites

No row-level benchmark or Earth Engine JavaScript is included in this repository. Obtain the public products listed in [`docs/data_sources.md`](../docs/data_sources.md), prepare authorized city-boundary and point assets in your own Earth Engine account, and reproduce the exports below. This is a documented input contract, not a preconfigured export command or a guarantee of byte-identical historical sample selection.

## General export procedure

1. Use authorized boundaries for Shenzhen, Kunming, Wuhan, Xian, Beijing, Chengdu and Hangzhou. Derive the three benchmark classes from 2020/2022/2024 Dynamic World and ESRI/Impact Observatory 10 m land-cover consensus, with 2020 GHSL built-up context for stable non-built samples. The historical development/external rule required consistent non-built states in all three years for class 0, consistent built states in all three years for class 1, and non-built 2020 plus built 2024 for class 2 in both land-cover products. Sample 6,000 points per class and city at 10 m, retaining the same point IDs and labels across annual exports. The original Shenzhen/Kunming selection used a private precomputed Dynamic World consensus asset, which is not distributed; fresh points are a protocol-level reconstruction, not the identical historical sample set.
2. At those fixed points, sample the annual AEF collection `GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL` separately for 2020, 2022 and 2024. Each CSV must contain exactly one numeric value for each canonical band `A00_{year}` through `A63_{year}`, plus `sample_id`, `city`, `class`, `longitude` and `latitude`. The two external cities additionally require `external_target` with a true value. Export geographic coordinates in EPSG:4326; the Python builders compute city-specific UTM coordinates and 2 km spatial blocks. Incidental Earth Engine columns such as `system:index` or `.geo` are not model features.
3. Name each file `AEF_{city}_{year}.csv`. Put Shenzhen/Kunming files in `data/raw/`, Wuhan/Xian/Beijing files in `data/imports/development/`, and Chengdu/Hangzhou files in `data/imports/external/`. Check every input declaration and approved export destination before running the Python builders. `scripts/01_build_dataset.py` creates the two-city processed Parquets; `scripts/06_multicity_dataset_integration.py` and `scripts/09a_external_dataset_audit.py` validate and process the later cities.

The annual files must agree by `sample_id` on city, class and coordinates, contain no duplicate/missing IDs, and have 64 finite numeric AEF bands for the stated year. City spelling must match the scripts. No raw CSV, point asset, private boundary asset or processed Parquet is bundled.

Classes: 0 Stable Non-built; 1 Stable Built; 2 Strict Expansion. AEF-192 comprises 64 annual bands from each of 2020, 2022 and 2024. Three temporal differences make AEF-195 but are **not** inputs to the final AEF-192 transfer models. Spatial blocks are 2 km in city-appropriate UTM coordinates. Latitude, longitude, city, IDs, block metadata and true class are never domain-classifier predictors.

If coordinates/labels are later released, document source asset, sampling derivation, EPSG/CRS, every column, class meanings and upstream license conditions in a separate approved data package. This repository intentionally contains only city-level map points/window metadata, not sample coordinates.
